# Задача: разметка фото теплосчетчиков

Ты размечаешь фото экранов квартирных теплосчетчиков для обучения модели распознавания показаний.
Каждую разметку потом проверяет человек, но твоя задача — сделать её максимально точной.

## Что делать

1. Найди партии в `batches/*/` без файла `IMPORTED.md`, где в `manifest.jsonl` есть фото, которых ещё нет в `labels.jsonl`.
2. Для каждого такого фото:
   - открой изображение (`file` из manifest, путь относительно папки партии) и внимательно рассмотри экран;
   - допиши в `labels.jsonl` этой партии **одну строку** JSON:
     ```json
     {"id": "<id из manifest>", "label": { ...поля по spec/label.schema.json... }}
     ```
3. Каждые 20 фото: запусти `python3 tools/validate.py`, исправь ошибки, сделай коммит и `git push`
   (сообщение: `labels: batch-XXX, N фото`). Так прогресс не потеряется, если сессия прервётся.
4. В конце — проверка, коммит, пуш и короткий итог: сколько фото размечено, сколько нечитаемых, какие были сложности.

## Правила

Полные правила — в [spec/prompt.md](spec/prompt.md), схема ответа — [spec/label.schema.json](spec/label.schema.json).

**Сначала реши итог (`outcome`)** — это главное поле:

| outcome | Итог | Когда |
|---|---|---|
| `read` | Показания считаны, верный экран | на экране энергия (Гкал, кВт·ч, МВт·ч), все цифры читаются |
| `wrong_screen` | Не тот экран | экран читается, но это не энергия: °C, м³, Δt, расход, серийник, тест 8888, дата |
| `unreadable` | Показания не распознать | цифры не прочитать: блик, размытие, угол, перекрыто, обрезано |
| `faulty` | Прибор неисправен | на экране ошибка (Err, Н.Ч., значок неисправности), видимое повреждение |
| `no_readings` | Нет показаний | экран пустой или погашен, либо экрана прибора нет в кадре |

Обязательные сочетания: `read` → `screenType: energy`, `readable: true`, непустой `valueText`, единица энергии;
`wrong_screen` → тип экрана не `energy`; `unreadable` → `readable: false`. Остальные поля заполняй во всех случаях,
насколько видно на фото (для `wrong_screen` тоже переписывай цифры — они нужны для обучения).

Главное по остальным полям:

- **valueText** — символы главной строки экрана ровно как показаны: цифры, точка, минус. Ничего не додумывай.
  Десятичную точку ставь только там, где сегмент точки реально горит. Ведущие нули сохраняй.
- **Неактивные сегменты** («призраки») бывают слабо видны — не путай их с горящими.
- Если хоть одна цифра не читается — `readable: false`, сомнения опиши в `uncertainDigits`.
- **screenType** определяй по значку единицы на экране (Гкал/Gcal, kWh, MWh, м³, °C, HEAT, SUM…).
  Температуру раздели: `temp_supply` — t1, подача (индекс 1 / T1 / F-Temp), `temp_return` — t2, обратка (индекс 2 / T2 / R-Temp);
  `temperature` — только если по экрану понять нельзя.
  Нужное показание — `energy`; остальные экраны (температура, объём, тест 8888, ошибки) тоже размечай честно — они нужны модели.
- **displayBbox** — рамка стекла ЖК-экрана основного прибора `[x0, y0, x1, y1]` в долях ширины и высоты (0..1), не всего корпуса.
  Основной прибор — ближе всего к центру кадра и крупнее остальных.
- **apartmentSticker** — рукописный номер на бумажной наклейке основного прибора (на соседнем — не считается).
- Не уверен в модели прибора — `other` и пояснение в `notes`.

## Чего не делать

- Не изменяй и не удаляй фото и `manifest.jsonl`.
- Не переписывай уже существующие строки `labels.jsonl` — только добавляй новые.
- Не редактируй `spec/` — он генерируется из основного проекта.
